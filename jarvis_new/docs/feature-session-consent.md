# Owner consent and session features

The agent registers `librarian_find`, `librarian_answer` and `librarian_duplicates` with an empty per-owner in-memory service. Local and existing personal/school Drive adapters perform no scan, token access, or content read at construction. A tool request without a reviewed source returns `needs_approval`. Source, content-read and model-disclosure permissions are separate. There is no model-callable consent/index configuration tool.

The owner can run the host-only command below, choosing an existing private owner directory and a new output filename. This writes only an expiring consent record, with exclusive creation; it neither discovers nor reads documents and performs no capture. Use a canonical local directory or one existing direct-child Drive folder, never a whole account. `--account` accepts only existing `personal` or `school`; it does not connect accounts or expand scopes.

```bash
python scripts/feature_consent.py /absolute/private/consent.json --screen-local-ocr
python scripts/feature_consent.py /absolute/private/study-consent.json --local-folder /absolute/study/folder --read-content --disclose-to-model
python scripts/feature_consent.py /absolute/private/drive-consent.json --drive-folder EXACT_FOLDER_ID --account school --read-content --disclose-to-model
```

Configure `JARVIS_FEATURE_CONSENT_FILE` with the reviewed record's exact absolute path before the next voice session. No home/default-file lookup occurs. Default duration is one hour; `--seconds` is limited to 60 seconds–seven days. Files must be regular, private, single-link and owned by the current UID, with no leaf symlink. Invalid/missing/expired consent keeps the normal assistant available and clears feature grants. Multiple approvals install atomically; a malformed grant purges earlier partial grants. Private-phone or guest transitions revoke source grants and screen authority; returning to owner does not inherit them. Shutdown drains both tracked text/realtime enrollment and screen work/local voice, then closes the derived index. Original documents/accounts remain untouched.

Screen activation is independently default OFF (`JARVIS_SCREEN_READING` must equal `1` in addition to host consent). The five-feature release explicitly keeps it `0`. Screen activation remains held for independent review of the conservative microphone/physical-stop behavior below; a consent file alone cannot enable it.

Explicit screen phrases are the ScreenService grammar: “look at my screen”, “read the selected window”, “read this error on my screen”, or “explain this page on my screen”. The adapter consumes a trusted final SDK user turn once. Realtime requires provider `item_id`; mirrored `ChatMessage.id` is deduplicated. Interims/VAD never cancel work or authorize capture. Missing IDs fail closed. New unrelated turns revoke pending screen scope; replacement requests wait for old cleanup. Echo filtering uses the existing session echo guard.

Screen MVP uses local OCR extraction plus cautious explanations of recognized error text; no freeform model reasoning or image upload is configured. The service's host-injected text-only explanation interface remains available for a separately reviewed provider. Default screen consent approves local text processing and private spoken output. The audio reply uses strict local Piper audio, `add_to_chat_ctx=False`, and awaits SDK playout. It bypasses the realtime say-to-model fallback. Cancellation interrupts/drains owned speech before private scope exits. The ordinary model receives only a content-free completion marker from any screen tool.

Before screen speech the adapter disables upstream SDK microphone input, clears the buffered user turn, disables SDK transcription output, clears the HUD tail, and suppresses persistent user/assistant captions. Quarantined transcripts/messages are masked and consumed, including late STT; they cannot mint task/capture/approval commands or enter the claim-user context. A speech-only stop can silence output without granting any authority. The physical SDK/app interrupt/close path and host `stop_private_output()` remain available. Microphone input stays disabled for this session; a new session restores it. Ordinary spoken barge-in while microphone input is gated is unavailable, and the actual app's physical stop route must be checked before enabling this screen mode. No transcript can re-enable input. Because the installed text-output callback has no reply ID, this conservative MVP keeps captions/transcription disabled for the rest of that session to reject late chunks; audio and ordinary claim guarding continue. Starting a new session restores normal caption behavior. OCR/images/answer locals are discarded; no screen answer is deliberately placed in agent/provider history. Acoustic echo/real device behavior still requires authorized live acceptance.

Exact final “stop”, “stop talking” or “be quiet” interrupts speech only. Explicit “cancel task task-ID” uses the authenticated local TaskTools adapter and original request identity. “Cancel this task” changes only one unambiguous unfinished task. “Cancel this tool” asks for an owned operation ID; it never infers PID cancellation. Registered cancellation/status/redirect/computer-use tools remain protected from tool tiering even when the fast path is disabled. A task receipt describes preparation lifecycle, not verified effects or rollback.

Health remains off until its existing explicit `JARVIS_HEALTH_RECORDER=1` opt-in. Build registration grants bounded observation only. This consent file grants neither process control nor WhatsApp sending. Restarting the app supplies no capture/document/send authority by itself.
